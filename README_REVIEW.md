# Personal Growth OS — исправленная локальная версия

Этот архив содержит исходники, исправления, тесты и технический отчёт (`AUDIT_RU.md`). Исходная база и секреты в архив не включены. Стек сохранён: React 19 / Vite 8 / TypeScript / Express 4 / Prisma 5 / SQLite.

## Важно перед обновлением существующего проекта

1. Не удаляйте оригинальную папку. Распакуйте исправленную версию отдельно.
2. Остановите API. Сделайте резервную копию всей исходной папки и SQLite (`dev.db`, а при наличии — также `-wal` и `-shm`). Не копируйте активную SQLite базу обычным файловым копированием во время записи.
3. Сначала обновляйте КОПИЮ базы. Архив не заменяет ваши `.env` и `dev.db` — их нужно перенести самостоятельно в соответствующие каталоги новой копии.
4. Не используйте `prisma migrate reset`, `db push --force-reset` или `--accept-data-loss` для рабочей базы.
5. Если в `.env` используются реальные ключи, храните архив приватно. При передаче третьим лицам или публикации замените ключи в кабинетах соответствующих сервисов.

## Требования

Node.js 22.12+ или актуальный Node.js 24 LTS, npm. Проверено на Node.js 24 в Linux. Старый Node.js 20 без нужного minor может не подходить для Vite 8.

Не переносите `node_modules` из Windows на Linux: переустанавливайте зависимости на целевой ОС.

## Новая установка

Из корня распакованного проекта:

```bash
cd apps/api
npm ci
cp .env.example .env
```

В Windows скопируйте `.env.example` в `.env` через Проводник/редактор. Проверьте:

```dotenv
PORT=3001
DATABASE_URL="file:./dev.db"
AI_PROVIDER=openrouter
OPENROUTER_API_KEY=
OPENROUTER_MODEL=deepseek/deepseek-chat
POSTBACK_TOKEN=
```

`file:./dev.db` у Prisma означает `apps/api/prisma/dev.db`, не `apps/api/dev.db`. AI-ключ нужен только для AI-функций. Отсутствие ключа не мешает запуску CRUD API. Заполните значения приватно, не публикуйте `.env`.

```bash
npm run db:generate
npm run db:upgrade
npm run typecheck
npm test
npm run dev
```

Во втором терминале:

```bash
cd apps/web
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5173`. API слушает только `127.0.0.1:3001`. Создайте проект в UI. Поле `VITE_API_URL` необязательно: пустое значение теперь корректно использует локальный адрес по умолчанию.

## Обновление существующей базы из исходного архива

После резервного копирования, переноса `.env` и КОПИИ `apps/api/prisma/dev.db`:

```bash
cd apps/api
npm ci
npm run db:generate
npm run db:upgrade -- --backup-confirmed
npm run typecheck
npm test
npm run dev
```

Скрипт работает только с SQLite. Если база в точности соответствует проверенной старой схеме, он отмечает восстановительную миграцию как уже присутствующую, затем добавляет `Conversion.externalId` и уникальный индекс. Если база отражает старую последовательность миграций, применяет недостающие изменения с сохранением `Lead.contact` как `Lead.handle`.

Неизвестное частичное расхождение схемы останавливает обновление. В таком случае не сбрасывайте БД: сохраните сообщение об ошибке и разберите различия отдельно. Скрипт не обещает автоматическое исправление любой произвольно изменённой базы.

## Публикация Telegram

- Настройки проекта: токен бота и ID канала. Токен после сохранения не возвращается через API; UI показывает факт сохранения.
- Пустое поле токена при сохранении означает «оставить текущий». Новый токен заменяет существующий. Отдельной кнопки удаления токена пока нет.
- Посты публикуются как plain text. HTML-разметка отключена, поскольку AI генерирует обычный текст.
- Автопубликация работает для `APPROVED` с наступившим `scheduledAt`, только пока API запущен.
- Генерация недельного плана происходит по кнопке. Старое поле дня генерации оставлено как задел, но отключено в UI.
- При отправке используется атомарный переход в `PUBLISHING`. Редактирование/одобрение/удаление отправляемого или опубликованного поста заблокировано.
- Изменение текста или заголовка одобренного поста возвращает его в `DRAFT` для повторного одобрения.

### Если статус `PUBLISH_UNKNOWN` или зависший `PUBLISHING`

Не нажимайте «повторить» вслепую. Таймаут мог произойти после фактической отправки, а сбой мог случиться между ответом Telegram и сохранением БД.

1. Проверьте сам Telegram-канал по тексту и времени.
2. Остановите API и сохраните резервную копию БД.
3. Если пост уже есть в канале, исправьте статус на `PUBLISHED`; если достоверно не отправлен — на `DRAFT`.
4. Изменять статус можно вручную через Prisma Studio (`npx prisma studio` из `apps/api`). Не изменяйте другие поля/записи.
5. Запустите API. При `DRAFT` заново проверьте/одобрите пост.

Это защита от повторов, а не гарантия exactly-once между Telegram и SQLite. Для полноценного восстановления нужны message_id, журнал попыток и отдельный интерфейс восстановления.

## Outreach

Telegram Bot API не рассылает личные сообщения произвольным людям по `@username`. Для отправки шаблона нужен числовой `chat_id` пользователя, который уже запустил этого бота. Учитывайте согласие получателя и ограничения Telegram.

В AI Outreach прежняя кнопка «Отправить» не имела обработчика. Теперь она честно копирует сгенерированный текст для ручной отправки. Отправка шаблонов остаётся в модуле лидов. Email/Telethon не подключались.

## Постбек трафика: изменён контракт

Постбеки по умолчанию отключены, пока не настроен длинный секрет:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Сохраните результат как `POSTBACK_TOKEN` в `apps/api/.env`, перезапустите API. Партнёрская система должна отправлять:

```http
GET /api/traffic/postback?clickid=<UUID>&eventid=<UNIQUE_PARTNER_EVENT_ID>&type=deposit&payout=100
x-postback-token: <POSTBACK_TOKEN>
```

`eventid` — уникальный ID конкретного события, НЕ просто clickid. Повтор того же события не начисляет доход повторно. Повторный eventid с другими параметрами отклоняется. Для разных партнёрок используйте префикс партнёра в eventid, чтобы избежать пересечений.

Токен не передаётся в URL и не сохраняется в `Conversion.raw`. Если партнёрка не умеет отправлять HTTP-заголовок, нужен отдельный проверенный адаптер; не убирайте авторизацию. Старый постбек без `eventid`/заголовка больше не поддерживается.

Внешняя партнёрка не достучится до локального API напрямую. Публичный endpoint, TLS, проверка отправителя, rate limiting и reverse proxy — отдельная задача. Не открывайте весь API наружу ради одного постбека.

## Загрузка сайтов

Разрешены HTTP(S) без credentials, только публичные IP и стандартные порты. Локальные/служебные адреса и DNS-rebinding блокируются. Редиректы отключены: при ответе 301/302 укажите конечный публичный URL. Ограничение ответа — 1 MiB, HTTP timeout — 10 секунд. Текст ограничен первыми 8000 символами.

## Проверки

```bash
# apps/api
npm run typecheck
npm test
npm run build

# apps/web
npm run build
npm run lint
```

Тесты API создают временные базы с синтетическими данными. Telegram/AI вызовы заменены заглушками. Рабочая `dev.db` ими не сбрасывается.

## Развёртывание

Это локальная single-user версия, не защищённый публичный SaaS. Bind, Host/Origin проверки и CORS не заменяют вход в систему. Для VPS нужны аутентификация/авторизация, TLS, резервные копии, ограничение запросов и отдельное безопасное раскрытие публичных маршрутов. Перед открытием внешнего доступа адаптируйте Host/Origin allowlist под проверенную схему reverse proxy, а не отключайте защиту целиком.
