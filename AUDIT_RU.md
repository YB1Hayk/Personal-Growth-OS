# Анализ Personal Growth OS

Дата: 13.10.2026. Основание: исходники и структура приложенного `Progect OP OM.zip`. Анализ БД ограничен схемой и историей миграций; личные записи не использовались для выводов. Реальные AI/Telegram-вызовы не выполнялись.

## Вывод

Проект — полезная основа **личной операционной системы маркетинга**, но не готовая автономная маркетинговая платформа. Сильная сторона — общий контекст проекта (DNA/voice), объединяющий контент, лиды, AI и трафик. Главный риск — разрыв между тем, что обещает интерфейс/roadmap, и тем, что фактически обеспечивает сервер.

Не рекомендую переписывать всё или сразу добавлять PostgreSQL/Redis/n8n. Для одного пользователя SQLite и текущий стек разумны. Приоритет: довести один реальный путь «проект → контент → одобрение → Telegram → лид → результат» до надёжности.

## Реальная готовность модулей

| Модуль | Есть в коде | Ещё не готово |
|---|---|---|
| Проекты | Создание, список, изменение DNA/voice/Telegram-настроек | Полноценное управление аккаунтами, публичная авторизация |
| Контент | AI-план, генерация текста, редактирование, approval, Telegram, cron | Instagram/Threads, надёжное восстановление отправок, автогенерация плана на сервере |
| Лиды | Ручной ввод, список, статусы, заметки, шаблонные касания | Реальный автоматический сбор из Telegram/LinkedIn/сайтов |

## Найденные проблемы и внесённые изменения

### Критические для запуска/безопасности

1. **Неполная история миграций.** Чистая установка не создавала часть текущей схемы (поля Project, таблицы контента/outreach/market, новое представление Lead). Добавлена восстановительная миграция и `db:upgrade`, который отличает проверенную существующую базу от исторической схемы. Старый `Lead.contact` переносится в `handle`. Нет reset.
2. **API слушал все сетевые интерфейсы без входа в систему.** Теперь bind только `127.0.0.1`, проверки Host/Origin, лимит JSON 64 KiB, отключён `X-Powered-By`. Это локальная защита, не полноценная аутентификация.
3. **Telegram-токен возвращался в ответах проектов.** Убран из create/list/update ответов, добавлен `hasTelegramToken`; пустой ввод не стирает токен. Поле ввода теперь password. Хранение токена в локальной SQLite всё ещё plaintext.
4. **SSRF при сканировании сайтов.** Сервис загружал любой адрес через axios с редиректами. Добавлены проверка публичных адресов, закрепление DNS для запроса, запрет redirect/proxy/credentials, ограничения размера, типа содержимого и времени. Старые ответы 301/302 теперь требуют конечный URL.
5. **Подделка и дублирование постбеков.** В исходной версии любой запрос мог записать выплату. Добавлены header-secret `POSTBACK_TOKEN`, обязательный `eventid`, уникальный индекс `Conversion.externalId`, обработка конкурентных дублей. Повтор eventid с другими параметрами отклоняется.

### Надёжность и корректность

6. **Повторная публикация при гонке ручной отправки/cron.** Оба пути теперь используют одну функцию с атомарным DB-claim. `PUBLISHING` блокирует повтор, `PUBLISH_UNKNOWN` исключает автоматический повтор после неопределённого исхода. Сломанный/пустой Telegram setup не отправляется. Exactly-once не обещается.
7. **Два расходящихся планировщика.** Старый scheduler публиковал APPROVED без проверки времени; теперь совместимый экспорт ведёт к общей реализации с `scheduledAt <= now` и `noOverlap`.
8. **Можно было повторно одобрить опубликованный пост/изменять отправляемый.** Добавлены ограничения переходов и изменений. Изменение заголовка/текста требует нового approval.
9. **Ошибки async в Express 4.** У traffic/market не было передачи rejected promises в middleware. Теперь есть asyncHandler и JSON error handler без выдачи содержимого Axios-конфига/токенов.
10. **AI JSON принимался без проверки структуры.** Недельный план валидируется как ровно семь объектов с непустыми полями; невалидный ответ не пишет записи. DNA/voice и извлечённый инсайт также проверяются. Стратегия контента ранее принималась аргументом, но не использовалась — теперь включается в prompt.
11. **Ошибки интерфейса.** Исправлены пустой `VITE_API_URL`, захардкоженный ID проекта, ISO-формат даты/очистка scheduledAt, выбор воскресенья и неверная надпись кнопки, которая обещала «перевести в черновик», а отправляла пост. Основные HTTP-ошибки больше не выглядят успешными операциями.
12. **Недельная генерация из React-effect.** Зависела от открытого браузера и устаревшего `posts`, могла повторяться. Убрана, поле помечено как нереализованное. Генерация по кнопке сохранена; серверная автопубликация сохранена.
13. **Смешивание проектов.** Проектные модули перемонтируются через key, история AI-чата не переносится в localStorage другого проекта, поздние ответы списка постов игнорируются.
14. **Outreach.** Проверяется принадлежность лида/шаблона/инсайта одному проекту; Bot API не пытается писать произвольному username. AI-кнопка без обработчика теперь копирует текст. После успешной отправки шаблона обновляется lastContact.
15. **Внешние вызовы без ограничений.** Добавлены таймауты Telegram и AI. Plain text вместо ошибочного HTML parse_mode. Убраны опасные логи с Axios-error/Telegram response. Один транспорт Telegram и общий Prisma-клиент.
16. **Не было backend build/test команд.** Добавлены typecheck/build/start и регрессионные тесты. Документы уточняют фактический стек вместо списка будущих библиотек.

## Результаты проверки

- Исходная версия: TypeScript backend/frontend проходил, несмотря на функциональные дефекты.
- Исправленная версия: `npm ci` API/Web, генерация Prisma Client, backend build и frontend production build прошли.
- `npm test`: **16 тестов, 16 passed, 0 failed**. Проверены конкурентная публикация, неопределённый исход отправки, расписание, защита токена, авторизация постбека, дубли, валидация, cross-project, SSRF-адреса, локальный доступ, обновление старой схемы и сохранение исторического contact.
- Web ESLint: **0 ошибок, 6 предупреждений** (dependencies React effects). Это оставшийся технический долг, а не скрытая успешная проверка без замечаний.
- HTTP smoke check: API `/`, `/api/projects` и frontend preview ответили 200 на синтетических данных.
- Полная визуальная/E2E-проверка браузером **не выполнена**: в окружении отсутствовал исполняемый Chromium. Не проверены реальная отправка Telegram, ответы AI, доставка партнёрских postback и продакшн-деплой.
- Обновление миграций проверено на искусственных наборах данных и сравнено со структурой базы из архива. Реальная пользовательская база не обновлялась.
- Полный dependency security audit, нагрузочное тестирование и проверка юридических/платформенных требований не проводились.

## Что ещё важно исправить

### Следующий приоритет: рабочий MVP

1. Подключить один настоящий Telegram-канал и проверить на тестовом канале все переходы статусов, формат, расписание и лимиты. Не начинать с массовых рассылок.
2. Добавить `telegramMessageId`, `publishedAt`, журнал попыток, классификацию ошибки и ручное подтверждение восстановления PUBLISH_UNKNOWN. Не включать безусловные retries.
3. Реализовать серверную генерацию контент-плана с timezone проекта, уникальной записью запуска «project + week» и ручным подтверждением перед публикацией. Сейчас расписание генерации отключено, а даты плана зависят от timezone сервера.
4. Сделать AI-chat историю действительно доступной модели; ограничивать длину/бюджет, хранить conversation по projectId. Сейчас модель видит только текущий message и общие поля проекта.
5. Учитывать реальные касания и результат лида. Не строить «самообучение» на вымышленных событиях или одних AI-выводах.

### Перед VPS/внешним доступом

6. Вход в систему, проверка доступа, TLS, ограничения частоты запросов и AI-бюджета, секреты вне клиентского bundle, резервное копирование и тест восстановления.
7. Разделить приватный API и публичные `/go`/postback; добавить проверку отправителя/события и retention для IP/userAgent/referer. При reverse proxy отдельно настраивать trust proxy.
8. Финансовые значения хранить в минимальных единицах валюты/Decimal, явно задавать валюту. Сейчас Float и отсутствие валюты ограничивают корректность ROI при нескольких партнёрках.
9. Добавить индексы под projectId/status/scheduledAt, постраничную выборку, регламент удаления логов/кликов. Сегодня большие списки загружаются целиком.

### Поддерживаемость

10. Разделить большой App.tsx на модули/хуки, единый типизированный API-клиент и контракты ответов. Существующие success/data и data/error форматы пока сосуществуют для совместимости.
11. Устранить оставшиеся warnings effects, расширить UI-тесты на переключение проектов, empty/error states, даты и rollback.
12. Отделить реальные статусы от демо-компонентов. Не показывать Instagram/Threads/автономного агента как работающие каналы до интеграции.

## Рекомендуемая продуктовая корректива

**Позиционирование:** «Личная рабочая панель для подготовки Telegram-контента и ведения лидов с AI», а не «автономная система, которая сама привлекает и закрывает клиентов».

**MVP:** один владелец, один Telegram-канал, ручной approval, CRM лидов, проверенная отправка opt-in контакту, учёт одного источника трафика. AI — помощник, а не источник фактов о доходах/результатах.

**Не добавлять сейчас:** новые соцсети, сложные очереди, миграцию на PostgreSQL, n8n ради самой автоматизации, масштабирование до появления реальной нагрузки.

Критерий готовности следующего этапа — не количество вкладок, а воспроизводимый цикл на реальных данных, без дублей и с понятным восстановлением после ошибок.
