# CLAUDE.md — Personal Growth OS

> Корректировки 13.10.2026: безопасный локальный режим, атомарная публикация, авторизация/идемпотентность постбеков, защита загрузки сайтов и восстановленные миграции. Новая установка и обновление старой БД описаны в `README_REVIEW.md`. Автогенерация недельного плана по дню пока отключена; UI не является серверным планировщиком. Трафик реализован как локальный модуль, публичный приём постбеков требует отдельного защищённого развёртывания.


## Проект

Ты строишь личную платформу автоматизации маркетинга и продаж. Это не SaaS — это инструмент для одного человека, поэтому приоритет скорость и функциональность, а не масштабируемость или красота кода.

---

## Стек

- **Frontend:** React + Vite + TypeScript + Tailwind CSS
- **Backend:** Node.js + Express + TypeScript
- **БД:** SQLite (файл `apps/api/prisma/dev.db`). Осознанный выбор для single-user сценария —
  не нужен отдельный процесс/контейнер, проще бэкапить (один файл), достаточно для нагрузки одного
  пользователя. PostgreSQL стоит рассматривать только при реальной необходимости масштабирования
  (несколько пользователей, конкурентная запись, объём данных, которому SQLite тесно) — не раньше.
- **ORM:** Prisma
- **Автоматизация:** n8n — задумано, в коде пока не подключено
- **Очереди:** Bull + Redis — задумано, в коде пока не подключено
- **AI:** OpenRouter (https://openrouter.ai) как единая точка доступа к моделям. Модель по
  умолчанию — `deepseek/deepseek-chat` (дешевле по токенам), переключение на любую другую модель
  (включая Anthropic Claude, напр. `anthropic/claude-...`) — через `OPENROUTER_MODEL` в `.env`,
  без правки кода. См. `apps/api/src/shared/ai/` (интерфейс `AIProvider` + реализации).
- **Хостинг:** VPS Ubuntu на Timeweb Cloud — целевая площадка, деплой пока не реализован
- **Деплой:** пока запуск локально (`npm run dev` в `apps/api` и `apps/web`). Docker Compose и
  деплой на VPS — будущий этап, см. раздел "Деплой на Timeweb VPS" ниже
- **IDE:** Google IDX

## 5 модулей платформы

### 1. Нишевой менеджер
Управление проектами. Каждый проект — ниша с контекстом: название, целевая аудитория, боли клиента, язык, подключённые аккаунты. Всё это — `project_context` в БД, который используют все остальные модули.

### 2. Контент движок
Генерация и публикация постов. Платформы: Telegram (Bot API + Telethon), Threads (API), Instagram (Graph API). Посты генерирует Claude под каждую платформу отдельно. Очередь постов с ручным апрувом или авто-публикацией по расписанию.

### 3. Лидогенератор
Сбор базы клиентов. Источники: парсинг Telegram-каналов (Telethon), LinkedIn (Apollo.io API), сайты (Puppeteer + Hunter.io для email). Все контакты в единой таблице `leads`: источник, статус, теги, история касаний.

### 4. Outreach менеджер
Персонализированные рассылки. Claude генерирует оффер под каждый лид на основе его профиля и `project_context`. Каналы: Telegram DM, email (SendGrid). Воронка: отправлено → открыто → ответил → заинтересован → созвон.

### 5. AI Sales агент
Claude с ролью продажника отвечает на первые сообщения, квалифицирует лида, предлагает Calendly-слот. Когда лид горячий — пуш в Telegram владельцу с саммари диалога.

## База данных — основные сущности

```
Project           — ниша/проект, корневая сущность
Account           — подключённый аккаунт (TG, IG, Threads)
ContentPost       — пост в очереди или опубликованный
Lead              — потенциальный клиент
OutreachTemplate  — шаблон рассылки
OutreachLog       — история касаний с лидом
MarketInsight     — инсайт из анализа рынка/сайта
ContentMetrics    — метрики поста (платформа, просмотры, реакции, клики). Реализовано на уровне
                    схемы и миграции — сбор данных не реализован
LeadContentTouch  — какой контент лид видел перед обращением + результат касания. Реализовано на
                    уровне схемы и миграции — логика фиксации касаний не реализована
LearningInsight   — агрегированный инсайт самообучения, ожидающий решения владельца. Реализовано на
                    уровне схемы и миграции — генерация инсайтов не реализована
TrackingLink      — связка "источник × креатив" для закупки трафика: /go/:slug редирект,
                    ручной ввод расхода. Модуль "Трафик" реализован полностью (API + UI)
ClickEvent        — клик по трекинг-ссылке; id передаётся дальше как clickid для постбека
Conversion        — конверсия из S2S-постбека партнёрки (registration/deposit + payout)

Conversation, AgentPrompt — из более раннего варианта плана, в текущей схеме их пока нет.
```

## Работа с AI (OpenRouter)

- Весь доступ к моделям — через `aiProvider` (`apps/api/src/shared/ai`), не напрямую через SDK
  конкретного вендора. Модули (`ai`, `content`, `outreach`, `market`) вызывают
  `aiProvider.generateText/chat/chatJSON`, а не создают свой клиент.
- Провайдер по умолчанию — OpenRouter, модель по умолчанию — `deepseek/deepseek-chat`. Переключение
  модели (в том числе на Anthropic Claude) или на альтернативный `OpenAIProvider` — через переменные
  окружения `AI_PROVIDER` / `OPENROUTER_MODEL`, без изменения кода модулей.
- Системный промт каждого агента хранится в таблице `AgentPrompt` (задел на будущее — редактирование
  через дашборд ещё не реализовано)
- Температура: `0.3` для продаж и outreach, `0.8` для контента — пока не параметризовано в коде,
  учитывать при реализации
- Всегда передавай `project_context` в системный промт агента

## Система самообучения

**Статус: реализовано только на уровне схемы БД** (`ContentMetrics`, `LeadContentTouch`,
`LearningInsight` — таблицы созданы, миграция накачена на `dev.db`). Логика сбора метрик, фиксации
касаний и генерации инсайтов ниже — это план на будущее, в коде её ещё нет.

Платформа анализирует результаты контента и диалогов, показывает инсайты в дашборде. Владелец сам решает что применять — система ничего не меняет автоматически.

### Принцип

```
Публикация → Метрики → Анализ (Claude) → Инсайт в дашборде → Владелец решает
Диалог с лидом → Итог → Анализ → Инсайт → Владелец решает
```

---

### Блок 1 — Контентный анализ (отдел маркетинга)

**Что собирается по каждому посту:**
- Платформа (TG, Threads, IG), формат (текст, рилс, карусель, сторис)
- Метрики через 24ч и 72ч: просмотры, реакции, репосты, сохранения, клики, охват
- Тема, хук (первые 10 слов), длина, наличие CTA, время публикации

**Что анализирует Claude:**
- Какие форматы дают наибольший охват в этой нише
- Какие хуки (первые строки) вызывают реакцию
- Какие темы резонируют — по реакциям и сохранениям
- Лучшее время публикации под конкретную аудиторию
- Паттерны провального контента — что стабильно не работает

**Как используется:**
Топ-10% постов по engagement rate автоматически помечаются тегом `top_performer`. При генерации нового контента Claude получает эти посты как примеры в системном промте:
```
Лучший контент этого проекта (бери за образец стиль и структуру):
[топ-посты с метриками]
```
Владелец видит в дашборде: "Рилсы с личной историей дают охват в 3.2x выше среднего — рекомендую увеличить их долю до 40%."

---

### Блок 2 — Продажный анализ (отдел продаж)

**Связь контента и лида:**
Когда лид приходит через органику (подписался → написал), система фиксирует какой контент он видел перед тем как написать. Это хранится в профиле лида как `content_touchpoints`.

**Что анализирует Claude:**
- Какой контент чаще всего предшествует входящему сообщению
- На каком посте/теме лиды "прогреваются" до обращения
- Какие возражения в диалоге коррелируют с определённым типом контента, который человек смотрел
- Какой стиль закрытия (мягкий / экспертный / срочность) работает для лидов с разным контент-путём

**Как Sales агент использует это:**
При начале диалога агент получает контекст лида:
```
Лид смотрел контент на тему: [темы]
Последний пост перед обращением: [текст поста]
Рекомендация на основе данных: лиды с таким путём лучше реагируют на экспертный тон, 
основное возражение — цена, закрывается через ROI-аргумент
```

**Инсайты для владельца:**
"Лиды, которые пришли после рилсов с кейсами, конвертируются в созвон в 2x чаще. Лиды после информационных постов чаще уходят на этапе цены."

### Схема БД

Актуальная версия — в `apps/api/prisma/schema.prisma` (миграция `20260705234626_add_learning_schema`).
Ниже — как реализовано сейчас; при необходимости можно расширить (например, разбить `views` на
24ч/72ч, добавить `engagementRate`/`isTopPerformer`) — но не раньше, чем появится логика, которая
это реально использует.

```prisma
model ContentMetrics {
  id          String      @id @default(uuid())
  postId      String      @unique
  platform    String      // TG | Threads | IG
  views       Int         @default(0)
  reactions   Int         @default(0)
  clicks      Int         @default(0)
  collectedAt DateTime    @default(now())
  post        ContentPost @relation(fields: [postId], references: [id], onDelete: Cascade)
}

model LeadContentTouch {
  id        String      @id @default(uuid())
  leadId    String
  postId    String
  result    String?     // OPENED | REPLIED | CONVERTED
  touchedAt DateTime    @default(now())
  lead      Lead        @relation(fields: [leadId], references: [id], onDelete: Cascade)
  post      ContentPost @relation(fields: [postId], references: [id], onDelete: Cascade)
}

model LearningInsight {
  id          String   @id @default(uuid())
  projectId   String
  module      String   // 'content' | 'sales' — тип инсайта
  title       String
  description String
  dataPoints  Int      @default(0) // сколько событий/метрик лежит в основе
  confidence  Float    @default(0) // 0-1
  status      String   @default("pending") // pending | noted | dismissed
  createdAt   DateTime @default(now())
  project     Project  @relation(fields: [projectId], references: [id], onDelete: Cascade)
}
```

### Когда запускается анализ

- **Контент:** каждые 24ч — сбор метрик постов, обновление `isTopPerformer`, пересчёт паттернов
- **Продажи:** после каждого завершённого диалога (созвон назначен / лид отказался)
- **Инсайты:** раз в неделю на проект — Claude анализирует накопленное и генерирует 3-5 инсайтов

Минимальный порог для инсайта: 15 постов с метриками для контентного анализа, 10 завершённых диалогов для продажного.

### Дашборд — вкладка "Аналитика"

**Контент:**
- График engagement rate по форматам и темам
- Топ-посты недели с объяснением почему они сработали
- Список инсайтов: "Посты с вопросом в хуке дают +47% реакций"

**Продажи:**
- Воронка по источникам контента
- Инсайты: "Лиды после кейсов → конверсия 34%, после советов → 12%"
- Профиль "идеального лида" на основе закрытых сделок

Статусы инсайта: `pending` (новый) → `noted` (принял к сведению) → `dismissed` (не актуально).

## Деплой на Timeweb VPS (будущий этап — пока не реализовано)

Ниже — целевая схема деплоя. Сейчас проект работает только локально (`npm run dev`), ни
`docker-compose.yml`, ни `.env` на VPS не существует. Возвращаться к этому разделу — когда появится
реальная причина выкатывать наружу, а не заранее.

```bash
# Первичная настройка
apt update && apt install -y docker.io docker-compose nginx certbot

# Запуск
git clone <repo> /opt/growth-os
cd /opt/growth-os
cp .env.example .env   # заполнить переменные
docker-compose up -d

# Фронтенд собирается в статику → /var/www/growth-os
# Nginx раздаёт статику и проксирует API и n8n
```

## Порядок сборки

Собирай модуль за модулем, не пытайся сделать всё сразу:

1. **Скелет** — монорепо, Prisma схема (SQLite), пустой дашборд — готово, без Docker
2. **Нишевой менеджер** — CRUD проектов, подключение аккаунтов
3. **Контент движок** — генерация + публикация в один канал
4. **Лидогенератор** — один источник (Telegram)
5. **Outreach менеджер**
6. **AI Sales агент**
7. **Система самообучения** — после того как накоплены первые реальные данные

Когда начинаешь новый модуль — сначала Prisma модели, потом API, потом UI.
